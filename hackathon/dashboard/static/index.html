Operating Systems Concepts & Detection Mechanics

1. Zombie Process Lifecycle (State 'Z' / Defunct)

When a Linux process finishes execution via exit(), the kernel frees its address space, memory pages, and open file descriptors. However, its entry in the process table (the Process Control Block / PCB) must remain so its parent can read its termination status code using wait() or waitpid().

Until the parent reaps the child, the process exists as a zombie. Zombies do not consume CPU or RAM, but an unchecked accumulation exhausts available PIDs (/proc/sys/kernel/pid_max), preventing new processes from spawning.

2. Orphan Process Reparenting

When a parent process terminates before its child, the surviving child becomes an orphan. In Linux, the kernel automatically reparents the orphan to the ancestor init process (PID 1) or an ancestor designated as a subreaper via prctl(PR_SET_CHILD_SUBREAPER) (e.g. systemd --user).

The adoptive parent periodically invokes wait() to reap reparented children when they eventually terminate.

3. Snapshot Heuristics vs. Controlled Verification

Crucial Systems Engineering Principle: A single snapshot of /proc showing PPID 1 cannot mathematically prove that the process was orphaned and reparented. Legitimate system services, background daemons, and init workers are spawned directly by PID 1.

Therefore, ProcessScope labels these snapshot entries as adopted_candidate. For definitive proof of orphan reparenting, ProcessScope provides a controlled experiment fixture (make demo-orphan) that monitors the process tree before and after parent termination.
